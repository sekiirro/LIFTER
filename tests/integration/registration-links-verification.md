## U6c offer-lock test (M7b re-run)

`tests/integration/registration-links-issue.test.ts` now opens connection A on the real `public.publish_package_version` inside a transaction (authenticated PO claims; the RPC's offer-row `FOR UPDATE` is held) and leaves it uncommitted. Connection B is a signed PO `issue_registration_link` call for the committed old version, started without awaiting. The test polls `pg_stat_activity` (loopback) for a `wait_event_type='Lock'` backend whose `pg_blocking_pids` contains A's pid and whose query is the issuance RPC, with a 10 s deadline. While A is open it asserts B has not settled and no old-version link row exists. It then commits A, awaits B, and requires `22023 stale_terms` plus zero link, installment and `registration_link.issued` audit rows; it also asserts the successor version is current. No timing sleep is used as the oracle.
