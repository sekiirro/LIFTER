# F16 Export and Read Isolation Contract

- F16 does not create client catalog endpoints. A client receives only explicit F17/F18 plan-version snapshots through the client plan path. Clients get no staff catalog or table access, and no catalog search, creator, origin, workspace override, or live food catalog read is exposed to them. Apart from frozen snapshot values (including trainer exercise Notes, S40-PO-8), the one live catalog-derived client value is the scoped video projection of FR-029, behind the F19/P4 wrapper.
- Exercise snapshots (`ExerciseSnapshotV2`, FR-027) preserve the canonical shared exercise identity, the exact selected canonical version, the override version reference and the planner-entry non-video values captured at publication, including copied defaults and subsequent trainer edits. The snapshot builder does not refresh these values from the current library. A workspace-private exercise uses the same V2 type with `source = workspace_private`: it carries the workspace exercise identity and version, with no canonical identity and no override reference (FR-027). Video stays live and follows the current authorized library value (S37-PO-1 Q2 = A). Trainer exercise Notes (the Notes of a workspace override and of a workspace-private exercise) are part of the client-visible frozen snapshot and of the F19/P4 client projection (S40-PO-8, PDN-S40-F16-06 = B); no visibility flag and no new client copy are added.
- Food snapshots preserve the exact food identity/version and the validated nutrition values used by the plan. A later edit, Remove, Restore, or merge cannot change an existing snapshot.
- A workspace exercise/video read resolves from the selected authorized workspace only. KENDO receives only KENDO's mapping; no TOJI URL, note, existence bit, candidate count, or error distinction may be returned, logged to a client-visible channel, or included in an export. The same rule applies with KENDO and TOJI reversed.
- Global search/detail projections may expose global content to PO and current coaching staff. Server-side RPC projections, views, exports, search, detail/history, duplicate warnings, errors and pagination metadata null or omit both `created_by` and `origin_workspace_id` for every non-PO actor. Only an explicit PO-only governance read returns those immutable provenance fields.
- Tests use isolated KENDO and TOJI fixture identities and links. Verify direct table reads, RPCs, search counts, detail/history, server projections, error paths, and plan/export joins. Mutation checks must make each tenant guard fail if removed. Do not use real production URLs or data as fixtures.
