## Approved submission payload calculation

In the worst case, each answer is 4,096 NUL bytes, which JSON escapes as 24,576 bytes, plus two quote bytes; each of 60 keys uses a valid 64-character ID (66 JSON-string bytes plus a colon), and the object has 59 commas and two braces. Maximum = 60 times (24,578 + 66 + 1) + 59 + 2 = 1,478,761 JSON payload bytes, before transport framing. This is about 90.3 times the pending 16,384-byte cap, so it does not fit. The 16 KB cap remains pending PO resolution; `maxPayloadBytes` is not described as approved.
