## Approved text and submission limits

The PO approved short text ≤150 and long text ≤1,000 characters, 256 KiB (262,144 bytes) per submission, server-side UTF-8 safety limits, and the existing 20 questions/section and 60/form bounds. Architect mapping: characters are Unicode code points; per-question `charLimit` may be lower (≥1), never higher than the type maximum. Each textual answer separately permits at most 4,096 UTF-8 bytes. Submission payload size is the sum of UTF-8 byte lengths of each answer value's JSON serialization, excluding question IDs, keys, envelope fields and transport framing. A ZWJ emoji sequence counts as multiple code points. The worst-case valid form of 60 long answers × 1,000 four-byte code points measures 240,120 bytes including JSON string quotes and passes below 262,144.

Measured synthetic realistic payloads use that answer-value JSON UTF-8 rule: EN short form values `Lina`, `Build strength`, `Train three days per week.`, `true` = **54 bytes**; AR long form values `أتمرن ثلاث مرات أسبوعيًا وأرغب في تحسين لياقتي.` and `أستخدم جهاز المشي وأمارس تمارين القوة منذ ستة أشهر.` = **102 bytes**; emoji-heavy values `🏋️‍♀️💪🔥` ×20, `👨‍👩‍👧‍👦` ×10, and `✅🌿` ×20 = **376 bytes**.
