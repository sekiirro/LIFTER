# Contract: Expiry notice RPCs, directory surface, and permissions

## RPC/API contract (proposed extension of existing APIs)

| Operation                     | Existing seam to extend                                                  | Contract                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Evaluate due stages           | Existing `workers/cron` scheduled dispatch → narrow DB evaluator         | System-only; acquire the same subscription lifecycle lock/order used by F13 writers; after waits, sample one authoritative timestamp, recompute current F13 state and Cairo end-boundary instant, re-resolve recipients and authorization, then scan/enqueue bounded due candidates atomically. Return aggregate counts/error codes only. No client PII in payload/results. |
| Read staff notices            | `public.read_staff_notices(limit,before)`                                | Authenticated recipient-only; validate limit/cursor; include existing notice fields and only safe subscription/client reference needed to link to the existing directory. Recheck current authorization.                                                                                                                                                                    |
| Mark staff read               | `public.mark_staff_notice_read(notice_id)`                               | Current recipient only; idempotent; safe `not_found` for foreign/unknown IDs; audit allow-listed kind.                                                                                                                                                                                                                                                                      |
| Dismiss staff notice          | Extend staff notice mutation family                                      | Current recipient only; one-way timestamp; cannot delete or alter another recipient's state; safe `not_found`.                                                                                                                                                                                                                                                              |
| Read client notices           | `public.read_client_notices(limit,before)`                               | Client self-only; include PRD expiry kinds; bounded stable cursor.                                                                                                                                                                                                                                                                                                          |
| Mark/dismiss client notice    | Extend `public.mark_client_notice_read` and add paired dismiss operation | Client self-only; idempotent per row; no renewal CTA or cross-account signal.                                                                                                                                                                                                                                                                                               |
| Read expiring/expired clients | Existing authorized staff directory RPC/service                          | Reuse directory route; filter/window in DB using one sampled instant and current F13 projection; `expiring` means `now <= expiry < now + 72 elapsed hours`, `expired` means current status `expired`; reuse existing `p_limit` max 100 and opaque cursor; count uses identical authorized predicate.                                                                        |

All functions keep empty search paths, owner/privilege patterns and narrow grants used by their owning migrations. No direct authenticated/service-role table access is added. Error outputs are stable generic codes, with foreign/unknown IDs indistinguishable.

## RLS / role permission matrix

| Role                            | Staff expiry notices                                                          | Staff expiring/expired list                                    | Client expiry notices                                              | Platform aggregate/drill-down                                  | P7 audit details                                         |
| ------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------- | -------------------------------------------------------- |
| PO                              | Own recipient rows plus explicitly approved platform notice scope             | All workspaces, via current PO capability and bounded filters  | None unless also acting as the client identity (separate identity) | Existing PO report permissions                                 | Existing PO audit access, but no extra P7 notice payload |
| WO                              | Own recipient rows for current own workspace only                             | Own workspace only                                             | None                                                               | Existing own-workspace reports only                            | Own existing audit scope; no P7-sensitive details        |
| Trainer                         | Own recipient rows for client workspaces where current coaching access exists | Client rows in workspaces where current coaching access exists | None                                                               | No platform aggregate; current permitted contextual reads only | No P7-sensitive details                                  |
| Sales                           | Denied; no notice or existence signal                                         | Denied; no staff list/count                                    | None                                                               | Existing explicitly granted report scope only                  | Denied P7 raw/activity detail                            |
| Client                          | No staff inbox                                                                | Denied                                                         | Own client notices only                                            | Denied                                                         | Denied                                                   |
| Anonymous/revoked/foreign actor | Denied                                                                        | Denied                                                         | Denied                                                             | Denied                                                         | Denied                                                   |

**Authorization walls**: application `authorize()`/server service and DB RPC/RLS; workspace and object identifiers supplied by clients never establish authority. Recheck after lock waits and at every read/mutation. Every Trainer with current coaching access in the client workspace is authorized for notice delivery and that client's expiry list row; access revocation denies reads while delivered rows remain stored. No direct table RLS bypass path is acceptable.

## State and response contract

- Notice state: `unread` when `read_at` is null; otherwise `read`; `dismissed_at` is an independent per-recipient state.
- Empty list returns an empty page, not an error. Unauthorized list returns generic denied/empty according to existing directory contract; it never returns foreign counts.
- Worker failure is retried by existing scheduler/outbox behavior; dedup identity is `(subscription, effective-expiry revision, stage)`, with recipient-scoped rows. Keep delivered rows and suppress obsolete due instants after an expiry change.
- One shared staff notifications surface in the staff app shell lists F15 form alerts through `read_form_alert_inbox` / `mark_form_alert_read` and `app/api/forms/alerts/route.ts`, plus F23 `staff_inbox_notices` and expiry kinds through `read_staff_notices` / `mark_staff_notice_read`. Reuse existing readers/mutations; add no inbox, table, job, or Realtime publication. UI copy is PROPOSED pending per-screen approval. The client directory list remains a filter on the existing `/clients` route.
