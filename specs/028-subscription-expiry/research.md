## Verified surface inventory and reuse decisions

- Client inbox producer: `app_private.f22_enqueue_client_notice`; client reader and state mutation are `public.read_client_notices` and `public.mark_client_notice_read`.
- Staff inbox: `app_private.staff_inbox_notices`; readers are `public.read_staff_notices` and `public.mark_staff_notice_read`. F15's `form_alert_inbox` is a separate Forms-specific surface and remains unchanged.
- F23 notice creation is producer-keyed and audited with allow-listed kind; notice rows are private and direct API grants are revoked.
- Client directory already accepts lifecycle state including `expired` (`supabase/migrations/20261223050200_f22_directory_assignment_filter.sql:66`); add an expiring window using F13 projection rather than another list.
- The actual app has `/clients`, `/reports`, client portal routes, and existing notice service adapters (`lib/progress-coaching/food-replacement/notifications.ts`, `lib/client-access/notices.ts`). Extend those surfaces.
- Existing cron/worker and purge controls are already singular. Add only new evaluator behavior through current dispatch and current purge owner; scheduled activation still needs its existing PO gate.

## Technical decisions

- F13's projector exposes `effective_end_exclusive` as a Cairo date, not an instant. Use F13 FR-004's existing conversion to the first existing instant of that Africa/Cairo date (nonexistent midnight resolves forward, ambiguous midnight uses earliest instant), then subtract exactly 72 elapsed hours for T-3. Example from F13: 2026-04-24 maps to 2026-04-23T22:00:00Z; T-3 is 2026-04-20T22:00:00Z. Reuse F13's gap/fold test fixtures; do not add a competing zone rule.
- Serialize evaluation/enqueue with lifecycle writers using F13's existing per-subscription lock order; after any wait, resample evaluation time, recompute the projected state/end, and re-resolve recipient authorization before insert. Recheck authorization on every read. Recipient interpretation is pending MCQ 028-01.
- For due stages, use a deterministic unique key over recipient, subscription, kind/stage (plus only the revision identity chosen by MCQ 028-03); existing unique producer seams are extended instead of creating a second outbox.
- Eligibility by F13 state: awaiting_activation has no known end and sends none; future/active/frozen use the projected end for upcoming stages; expired emits only the expiry stage except short-lead catch-up under MCQ 028-02; refunded/deactivated/closed/purged suppress new stages. Re-evaluate under the shared lifecycle lock on each pass.
- Re-evaluate current F13 lifecycle state and expiry each scheduled pass. If a stage has not been delivered and the effective end changes, stale due predicates do not enqueue; renewal/freeze/refund/close/purge update behavior stays source-owned.
- Fetch on open and refresh after read/dismiss; no Realtime publication is added, consistent with P7 notification/privacy restrictions and avoiding a new authorization channel.
- Names/expiry labels are resolved through currently authorized directory query; inbox rows/worker payloads keep IDs and allow-listed kinds only.
