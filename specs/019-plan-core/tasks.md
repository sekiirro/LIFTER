## Dependency order

T001-T005 are independent and may start before F16 or Plan Core merge. T006-T007 establish identity and immutable revisions after F16 contracts and stack assignment; T008 may proceed against fixtures after T001/T003. T009-T012 depend on T006-T007 and the F16 idempotency/security conventions. T013-T016 depend on the Plan Core root/revision model and F16 contract merge; T013 is the delivery-ownership merge gate and T024 is a merge gate; T017 can proceed from mocked projections. T018 depends on F16 snapshot contract. T019-T020 require the database stack and implemented RPCs. T021 can start against fixtures, then bind to the integrated UI. T022 depends on T015-T016. T023 is a handoff after consumer contracts are available.

## Parallel execution

T001, T002 and T003 can run concurrently because they add separate contract/schema files. T004 and T005 can run concurrently because they own separate component and test files. T008, T017 and T018 can run concurrently after their referenced fixtures/contracts are available; they own separate files. T021 can run alongside T017 using mocked projections. Database tasks use a single assigned stack lane and should be serialized where migrations or shared RPC files overlap.
