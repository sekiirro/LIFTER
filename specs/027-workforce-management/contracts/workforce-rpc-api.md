# Contract - Workforce API/RPC

Logical contract only. Route/function names are not approved. Every operation derives actor from authenticated server context and validates workspace/source/person scope. Caller-supplied role never grants access. Use canonical decimal strings for points and exact minor units plus currency for money.

## Audit, retention and read channel constraints

- P7 financial/KPI audit_events details contain opaque reference only; amounts, reasons, salary and employee KPI detail live in PO-only P7 records. Preserve unrelated WO audit rights.
- P7 retained earned facts have no client FK/PII. F26 allowlist/unlink path handles client-linked follow-up/questionnaire records. Open tied disputes pause purge; resolution restarts 30 days.
- Deny raw P7 detail through Realtime/publications, broadcast, HEAD/count/existence/search, notifications, exports, caches and idempotency receipts. Sales gets no P7 result before both month-end and PO finalization.
- Errors are non-disclosing. Transactions cannot partially write business event, P7 fact, audit reference or replay receipt.

## Atomicity and ordering

- Source locks precede one workspace+month period fence for every point producer, manual edit, refund/reassignment and close. Use one documented lock order and cover first period event and multiple staff.
- Unique logical source/occurrence keys prevent duplicate entries even when request idempotency keys differ.
- F13 refund reversal/questionnaire/deduction obey F13 source lock/revision. Questionnaire uniqueness is separate from reversal uniqueness.
- Concurrent PO revisions use optimistic expected version. Payroll approval is a unique employee+month entitlement bound to reviewed snapshot; different keys cannot duplicate it.
- Authorization is rechecked after waiting. Any failure rolls back point, money, audit reference and replay receipt together.
