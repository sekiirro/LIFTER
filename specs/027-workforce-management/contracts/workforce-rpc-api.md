# Contract - Workforce API/RPC

Logical contract only. Route/function names are not approved. Every operation derives actor from authenticated server context and validates workspace/source/person scope. Caller-supplied role never grants access. Use canonical decimal strings for points and exact minor units plus currency for money.

## Audit, retention and read channel constraints

`public.p7_get_own_compensation(p_employee_id uuid, p_effective_month date)` is the implemented monthly read RPC. It returns exactly six fields: `basic_salary_amount_minor`, `basic_salary_amount`, `currency`, `approved`, `approved_snapshot_total_minor`, and `approved_snapshot_total`. The two amount fields for each amount use exact minor units and a canonical two-decimal string. Snapshot total fields are null until approved. Trainer and Sales identity is taken from `auth.uid()`; a different target id, a WO, anon, or an identity without an eligible staff role receives `not_permitted` (SQLSTATE `42501`) before any salary or approval lookup. The platform PO may request any target staff id. The projection reads only salary revisions and payroll approvals; it contains no points, KPI, penalty, or attribution data.

- P7 financial/KPI audit_events details contain opaque reference only; amounts, reasons, salary and employee KPI detail live in PO-only P7 records. Preserve unrelated WO audit rights.
- Strike event and correction tables have RLS enabled and forced, no direct staff grants, and PO-only RPC access. `getRollingStrikes` and `correctWorkforceStrike` authorize the platform PO before resolving event keys, source keys, aggregates, or replay data; Trainer, WO, and Sales cannot read or correct strike records. Responses and audit details contain no client identity/PII. Strike correction is append-only and separate from every point correction path.
- A strike is recorded for the persisted F15 D-03 breach instant when no initial plan pair has succeeded by the deadline, even if no later delivery occurs. The source key is unique per client+initial subscription and opaque; later delivery does not change the strike timestamp or produce another strike.
- Corrections require a reason. Latest correction determines effective state; void excludes the strike, reinstate reverses the latest void, and reattribute changes the counted Trainer only to a same-workspace Trainer who had access at breach. Each append is serialized per strike so concurrent corrections cannot lose ordering.
- P7 retained earned facts have no client FK/PII. F26 allowlist/unlink path handles client-linked follow-up/questionnaire records. Open tied disputes pause purge; resolution restarts 30 days.
- Deny raw P7 detail through Realtime/publications, broadcast, HEAD/count/existence/search, notifications, exports, caches and idempotency receipts. Sales gets no P7 result before both month-end and PO finalization.
- Errors are non-disclosing. Transactions cannot partially write business event, P7 fact, audit reference or replay receipt.

## Atomicity and ordering

- Source locks precede one workspace+month period fence for every point producer, manual edit, refund/reassignment and close. Use one documented lock order and cover first period event and multiple staff.
- Unique logical source/occurrence keys prevent duplicate entries even when request idempotency keys differ.
- F13 refund reversal/questionnaire/deduction obey F13 source lock/revision. Questionnaire uniqueness is separate from reversal uniqueness.
- Concurrent PO revisions use optimistic expected version. Payroll approval is a unique employee+month entitlement bound to reviewed snapshot; different keys cannot duplicate it.
- Authorization is rechecked after waiting. Any failure rolls back point, money, audit reference and replay receipt together.
