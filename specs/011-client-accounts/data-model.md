## Tenant entity: public.clients

All columns NOT NULL unless marked nullable. No password, token, copied package price or subscription. Required name and pending-approval follow ND-F11-3/6; state representation is technical design, no approval UI inferred.

| Column               | Type                    | Constraint/source                                                                                                                    |
| -------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| id                   | uuid                    | PK, server generated; UNIQUE `(workspace_id,id)`                                                                                     |
| workspace_id         | uuid                    | FK workspaces(id), ON DELETE RESTRICT; derived from locked link                                                                      |
| auth_user_id         | uuid                    | UNIQUE globally; FK auth.users(id), ON DELETE RESTRICT; no staff profile for same identity                                           |
| registration_link_id | uuid                    | UNIQUE globally; composite FK `(workspace_id,registration_link_id)` → registration_links(workspace_id,id), ON DELETE RESTRICT        |
| package_version_id   | uuid                    | Composite FK `(workspace_id,package_version_id)` → package_versions(workspace_id,id), ON DELETE RESTRICT; exact match to issued link |
| email_normalized     | text                    | UNIQUE globally, nonempty; DB recomputes using ND-F11-2 seam; no ad hoc lower/trim default                                           |
| phone_e164           | text                    | UNIQUE globally, nonempty canonical E.164 output from ND-F11-2 seam; input/country handling unresolved                               |
| name                 | text                    | Required signup name (ND-F11-3); no invented length bound                                                                            |
| approval_state       | proposed representation | Initially pending-approval; no client access until admin approval (ND-F11-6); approval action/roles ND-F11-6a open                   |
| created_at           | timestamptz             | Server insert time only                                                                                                              |

A future composite UNIQUE `(workspace_id,id,package_version_id)` on registration_links supports a three-column client FK `(workspace_id,registration_link_id,package_version_id)` to bind the exact issued version declaratively, in addition to ordinary tenant FKs. Derive offer via that immutable version's same-workspace offer FK; do not accept offer/workspace/terms from the caller. Keep the existing immutable link installment rows as the issued schedule. Current publication/availability changes do not invalidate or rewrite an issued association. No F12 effects.

Index workspace/id for scoped existence and Auth user for F4 lookup (unique indexes already cover both). Inserts must verify a valid locked link, no existing consumed marker, no same-identity staff profile and exact canonical-claim ownership. UNIQUE/foreign-key checks, not prechecks, are the race backstop. A deferred integrity check verifies client ↔ consumed link ↔ Auth identity correspondence at commit; every new consumption must have exactly one committed client, every client must have its consumed link. No standalone consume function is exposed.

## Global identity security index: app_private.account_identifier_claims

This is a global identity constraint registry, not tenant-owned client content. It includes existing staff/Auth identities, including platform staff with no workspace. It must not invent a fake workspace for them. Columns: `auth_user_id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE RESTRICT`, `email_key text UNIQUE`, `phone_key text UNIQUE`, `created_at timestamptz NOT NULL` server time. Nullable identifier fields permit existing identities without phone/email, subject to ND-F11-9; client creation requires both. No PII from this table is publicly selectable.

Client UNIQUE columns enforce global client/client collisions independently. Claims UNIQUE keys enforce collisions against other account identities. DB triggers/functions synchronize claims for **all** Auth email/phone mutations and client-contact mutations, and enforce staff/client mutual exclusion on both classification directions. Client contact phone need not be an Auth phone-login identity: a NULL Auth phone must not erase the client's existing phone claim. A non-NULL Auth phone must agree with the same user's canonical phone claim or be rejected; no silent overwrite/release. Source-authority and identifier release semantics come only from ND-F11-2/9.

Future migration must backfill known identities using the approved canonicalizer, compare registry/client/Auth consistency, and fail on unresolved collisions or missing policy. Do not merge users, choose a winner, change old migrations/seeds, or claim Auth's current email index is sufficient. Concurrent staff creation/identifier change must contend on the same canonical keys. Registry writes use sorted advisory key locks as an ordering aid and UNIQUE as enforcement. All paths must use the same order; deadlocks/serialization aborts are safely retried with the same request identity. ND-F11-7/9 block release/pseudonymization design; no automatic deletion is authorized.

## Private signup operation and attempt records

`app_private.client_signup_operations`: committed receipt only; tenant-owned, mandatory `workspace_id`, composite link FK and UNIQUE link; UUID operation ID with UNIQUE `(workspace_id,id)`, `auth_user_id uuid UNIQUE REFERENCES auth.users(id) ON DELETE RESTRICT`, hashed high-entropy request secret, server timestamps and composite committed-client FK. Insert atomically with Auth/client/consume/audit. Never store password, raw token, email/phone or raw request secret. Immutable after insert; no reservation, lease, fence or cleanup state. At most one committed Auth identity per link; receipts never recover public success/session.

`app_private.client_signup_attempts`: tenant-owned, mandatory workspace, generated UUID admission-ticket PK, UNIQUE `(workspace_id,id)`, composite link FK, composite operation FK when present, `request_secret_hash text NOT NULL`, `admitted_at timestamptz NOT NULL`, `redeemed_at timestamptz NULL` and minimal admission evidence. No signup identity field, registration-token/hash or provider body. Stored client IP for the 30/IP/hour limit is PII; trusted source and non-forgeable transport are AD-F11-2 technical design, never an arbitrary public caller IP. The proposed link-bound ticket schema is not a complete IP/invalid-attempt log design: technical design must support durable attempt/failure coverage, including invalid/unresolved links without fabricated tenant/link references, and atomic 30/IP/hour enforcement across different links/workspaces. Trusted IP provenance remains AD-F11-2. Count attempts in a durable admission transaction under the locked link; redemption verifies link/request-secret hash and a guarded NULL→timestamp transition. The direct RPC keeps redemption outside the protected inner signup subtransaction, catches sanitized failures and commits redemption even when inner Auth/client/consume/audit effects roll back; explicitly force deferred checks inside the inner unit before success. No unlimited failed hash retries on one admission. An outer transport/transaction abort is ambiguous and must require fresh admission and authoritative receipt checking before retry, with tests for this boundary. Enforce BOTH 5/link/15 minutes and 30/IP/hour, generic exhaustion; attempt definition and rolling/fixed semantics remain ND-F11-5a. Durable attempt/failure evidence survives signup rollback. Purge signup-attempt logs including stored IP after 30 days, preserving one-use/committed receipt guarantees. Other audit retention undecided, ND-F5-1/B4 unchanged. Event names/payload allow-list are technical design.

Receipt/request secrets are credentials: random at least 32 bytes, only hash persisted, never audited/logged/cached. They bind an internal operation, never grant client/profile access or recovery of completion. Every consumed-link replay is generic invalid, including a matching secret after response loss. Client refresh/retry retains the secret safely for that submission without persistent analytics/local-storage exposure. Expiry/retention must preserve link-bound at-most-one identity; technical dedup cannot expire into a second signup.

## RLS, grants and guards

Enable and FORCE RLS on all four proposed tables. Revoke ALL table privileges from PUBLIC, anon, authenticated and service_role, including defaults. No anon table policy, general INSERT/UPDATE/DELETE/TRUNCATE grant or wildcard SELECT. Private tables have no end-user policies or API schema exposure. Postgres-owned narrow functions use empty `search_path`, fully qualified objects, validated arguments and revoked default EXECUTE. An elevated owner bypasses RLS: function checks are mandatory independent authorization, not a claim that FORCE RLS restrains that owner.

Exact end-user column grant inventory: **none** on clients or the three private tables. Explicitly withhold workspace/id/Auth-ID/email/phone/link/version/timestamp columns, wildcard SELECT and all writes. F4 already uses guarded RPC/helper lookup; this unit adds no client-list reader or client self-read/write policy. No new SELECT policy or safe view is needed: forced RLS defaults deny. Any future protected reader requires existing app `authorize()` and a scoped RLS policy using `has_workspace_access()` plus separately reviewed column grants, not an implied entitlement here. Isolated RLS mutation probes may fixture-grant a safe column inside a rolled-back test transaction only.

Public callable `public.client_signup_admit(token text, request_secret text)` and `public.client_signup(token text, request_secret text, admission_ticket uuid, fields jsonb)` receive EXECUTE only for anon/authenticated, never service_role; server signup calls use anon/publishable credentials only. No signup service-role grants or admin orchestration. Before any write, both RPCs invoke C1: latest `auth.schema_migrations` in the explicit locally captured GoTrue v2.197.0 allowlist and presence/types of every column written. Failure returns generic unavailable, no write or consumption. C3 uses `extensions.crypt(..., extensions.gen_salt('bf', <GoTrue cost>))` with captured local cost and no plaintext in exceptions/RAISE/audit/logs/receipts/returns. Do not insert generated Auth columns. C2 requires real sign-in and exhaustive reference-row parity; C4 blocks hosted deployment. No grants are applied in this design run.

clients: immutable identity/workspace/snapshot/created_at after insert; initially pending-approval. Both app authorization and DB RLS deny client capabilities until approval; approval action/roles remain ND-F11-6a, no transition UI invented. Claims: guarded synchronization only, never arbitrary reassignment. Operations: immutable committed receipt/binding/secret; attempt records immutable except the guarded one-use redemption marker. Clients/claims/operations have BEFORE DELETE row and BEFORE TRUNCATE statement guards using F10's `forbid_delete()` pattern, even for privileged integrity probes. UPDATE rejection uses the existing immutable-trigger pattern except tightly guarded admission redemption and claim synchronization. Attempts need a narrowly authorized local 30-day purge path guarded against deleting younger records, with structured cleanup evidence and no general DELETE/TRUNCATE grant or weakened one-use/receipt integrity. Client FK RESTRICT forbids deleting a committed identity. Closure/pseudonymization remain future reviewed work, never bypass these guards casually.

Preserve F10 snapshot/schedule guards. Future consumed-marker guard extension changes only signup's NULL→value transition to use fresh authoritative time and client correspondence; it preserves set-once markers, no-op rejection, all immutable columns and first-open rules. No direct marker UPDATE grant. A client insert followed by zero-row guarded consume raises and rolls back, including any Auth writes.

## Audit extension from latest F10 body

Start from **the complete** `app_private.audit_row_change()` in `supabase/migrations/20261030120000_registration_links.sql`, not the F4/F9 body. Preserve unchanged mappings and detail allowlists for: workspaces INSERT/name/slug UPDATE; staff_profiles INSERT/role UPDATE; workspace_memberships INSERT/revocation; recovery_link_issuances INSERT; packages; package_versions; package_offers availability; registration_links issued including final installment count/text price/currency and first-open-only; jobs dead-letter status; no-op returns; unmapped-table exception; final append-only insert, owner, search_path and revoked EXECUTE.

Append clients INSERT branch and extend the registration_links branch for consumed NULL→value only, without displacing opened/issued logic. Trigger once per client insertion and once per actual consumption, not manual duplicate RPC audit inserts. `app_private.client_signup_audit_contract()` solely owns event vocabulary/actor/details: **Decided: structured attempt/success/failure/consumption/cleanup without secrets; names/payload allow-list technical design (ND-F11-10)** as listed in plan. Synthetic events `client.created` and `registration_link.consumed` correlate only same-workspace client/link UUIDs, never credentials, canonical identifiers, colliding-field/account details, metadata, phone/email or provider payload. Public actor remains NULL in synthetic cases; never impersonate issuer or newly created user. Signed-in visitors must manually sign out before registering, no auto sign-out/linking/merge. Event names, actor representation and payload allow-list are technical design; event coverage is decided.

Audit failures and deferred checks abort the whole successful-change transaction. Attempts/denials cannot emit successful events. Exact replay emits none. Preserve all historical F4/F9/F10/job audit tests and compare the complete old branch inventory in the future migration review.

## Decided identity scope and expiry

DB uniqueness prevents active/pending duplicates using Supabase Auth email normalization and E.164 phone. Archived collision returns generic D-08/admin review; mechanism/reviewer ND-F11-9a and absent archived state ND-F11-9b remain open, archived behavior blocked until ND-F5-1 closure. D-16 unchanged; no archival/release transitions invented.

Signup requires authoritative consumption time strictly before `expires_at`, no grace. F10 open/grace behavior and contract remain unchanged: a grace-open may render valid but signup returns generic invalid. Public-page alignment is ND-F11-4a. Maximum password length/symbol definition ND-F11-1a and destination/session ND-F11-6b remain open (no client access either way).
