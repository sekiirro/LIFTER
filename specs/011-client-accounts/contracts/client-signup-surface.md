## Public transport and admission

GET `/register/[token]` keeps F10's dynamic/no-store open behavior and minimal workspace-name/validity projection. Add a POST Server Action on the **same exact single-segment route**, with framework origin/CSRF protection, server-side payload validation and no state-changing GET signup. Do not put passwords/tokens/PII in query strings. Browser sends token only as the necessary route/action credential, a random per-submission request secret, and required name/email/phone/password (no Telegram) permitted by `signup_field_contract()`. Bound action values are still secrets; never serialize the token in visible success/error props or metadata. Reject caller workspace, offer/version, auth-user ID, role, grant, timestamp and terms overrides.

`authorizePublicClientSignup()` is the app wall: validates token/request-secret shape, same-origin submission, allowed fields/visitor policy and durable per-link and per-IP admission through the bounded admission RPC before expensive hashing. It does not call staff `requireActor()` (which redirects) or invent a client capability. The database wall independently hashes the token, resolves/locks its row, derives workspace/snapshot, checks time, admission/request binding, canonical ownership and all constraints. Direct callers of the public RPC must pass those DB checks too. No trust in caller scope, app precheck success or service-role bypass.

Protected staff surfaces still require existing `authorize()` and `has_workspace_access()`. Clients/Auth-only users have no staff role/membership; this unit grants none. An architect must review the bounded definer path as the public analogue of F10, with no broad anon RLS policy.

## Proposed bounded RPC shapes

- `client_signup_admit(token text, request_secret text, ip_key bytea, link_key bytea, issued_at timestamptz, nonce uuid, attestation bytea) → {status:'admitted',admission_ticket:uuid}|{status:'invalid'|'unavailable'}`: durable per-link and per-IP attempt transaction; unknown/invalid tokens do not disclose scope. The DB verifies attestation/freshness/nonce and token-to-link_key binding, then atomically counts under advisory link-key then ip-key locks, checks ND-F11-5, and records minimal evidence. The admission ticket is a one-use credential bound to the link and hashed request secret; it is not an Auth ID or workspace disclosure. No Auth reservation is created by this public call.
- `client_signup(token text, request_secret text, admission_ticket uuid, fields jsonb) → SignupResult`: option (i) bounded transactional signup; minimum 8-character password including number and symbol (maximum/symbol definition ND-F11-1a open), Supabase Auth email normalization, E.164 phone and mandatory shape/limit checks apply to direct calls as well as app calls. A public caller cannot forge successful admission by setting a JSON flag. Admission tickets (separate from attempt logs) must bind link + request-secret hash and be consumed exactly once by the write operation. Redeem before entering an inner write subtransaction; catch business failures and commit redemption while rolling back every inner signup effect; infrastructure failures roll back redemption too. Force deferred checks inside the inner unit. A new failed-write retry requires fresh durably counted admission. An exact concurrent request waits and returns generic invalid if the first committed.

RPC shape is a proposed technical contract under AD-F11-1 PENDING PO and proposed evaluation criteria C1–C4, not an implementation. Infrastructure exceptions/provider/constraint details are adapted server-side and never passed through.

## Public SignupResult and privacy equality

Business outcomes render HTTP 200, with one constant-shape body containing only a status and translated generic text. Infrastructure failures MUST use a generic 503, still with privacy headers and no provider details. Field-validation feedback is permitted only for the submitter's allowed input, never account lookup results.

| Internal class                                                                                                                                                                  | Public result                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unknown/malformed/expired/consumed link, wrong replay secret, forged binding                                                                                                    | `{status:'invalid'}` plus the same F10 generic invalid message; no reason code, validity date or workspace ID                                                                       |
| Email-only/phone-only/both collision, same/foreign workspace, active/pending/staff collisions and archived collision (generic D-08/admin review; behavior blocked on ND-F11-9b) | `{status:'duplicate'}` plus **“This email is already registered. Contact support.”**, equivalent Arabic translation; no field discriminator, account ID, workspace or provider code |
| Confirmed initial committed signup                                                                                                                                              | `{status:'complete'}` plus generic completion; no Auth/client ID, token, profile or financial data                                                                                  |
| DB unreachable / C1 guard failure / admission-attestation infra failure / unexpected exception after rollback                                                                                                  | `{status:'unavailable'}` plus generic translated retry text; no SQL/provider exception                                                                                              |
| Allowed form validation error                                                                                                                                                   | `{status:'invalid_input'}` with safe field feedback from approved field/password seam, no submitted values echoed                                                                   |

Invalid link checks precede uniqueness, including for requests with colliding inputs. Duplicate classes must have identical status/body/headers and UI wording; avoid identity-specific timing branches and benchmark for obvious timing leakage without inventing a new latency SLA. Enforce BOTH 5/link/15 minutes AND 30/IP/hour; either exhausted limit returns generic non-disclosing feedback, never consumption. Attempt definition and rolling/fixed windows remain ND-F11-5a. Counts and attempt/failure evidence commit in durable admission independently of signup rollback. Attempt logs contain no IP/ip_key; HMAC counters expire at window end (+ small slack), subject to C1 privacy proposal PENDING PO / NEEDS SOURCE CONFIRMATION. Trusted IP and the expanded attestation RPC follow AD-F11-2 below. Do not import F10 issuance limits.

## Lock order and atomicity

**Lock order (verbatim contract):** `link row FOR UPDATE → validity with authoritative clock_timestamp() after lock → request/ticket redemption (pre-admitted in a separate transaction) → canonical uniqueness locks in sorted key order and DB constraints → Auth identity/claim writes → client insert → guarded consume with fresh authoritative time → receipt and audit → deferred checks → COMMIT`.

**Transaction boundary (verbatim contract):** `Client insert + guarded registration-link consumption + successful-change audit (including deferred checks) + Auth user/identity + canonical claims + committed receipt commit in one database transaction; any failure rolls all signup effects back. Durable admission is separate; one-use ticket redemption precedes the inner signup subtransaction and business failures commit redemption without signup effects; infrastructure failures roll back redemption and return unavailable.`

Admission uses advisory link-key then ip-key locks separately from signup row locks and commits minimal evidence before hashing; it is not a validity reservation. C1 guards both RPCs before any write, including ticket redemption. Consumed-link retries always return generic invalid; internal committed receipts prevent duplicate identities but never recover public success/account/session. No provider HTTP or saga exists in signup. C3 requires server anon/publishable-key signup RPC calls only, bcrypt `extensions.crypt(..., extensions.gen_salt('bf', <GoTrue cost>))`, and no plaintext in exceptions/RAISE/audit/logs/receipts/returns. C2 real sign-in and exhaustive GoTrue-set-column parity must pass locally; C4 blocks hosted deployment pending re-verification and PO approval.

Guarded consumption: UPDATE the exact derived workspace/link with `consumed_at IS NULL` and `fresh_authoritative_time < expires_at`, set consumed_at to that same fresh instant and require one `RETURNING id` row. Zero rows raises/rolls back. Sample again after expensive hash/constraints; do not use transaction-start `now()` after a lock wait. Signup is strict, no grace, equality invalid. F10 open/grace behavior and contract remain unchanged: a post-expiry grace open may render valid but signup returns generic invalid. Public-page alignment ND-F11-4a would require PO-approved F10 change. Future guard extension must agree with the consume timestamp and preserve all F10 protections.

## Headers, middleware and token handling

Every registration GET/POST response, including invalid, duplicate, field error, rate exhaustion, success, missing configuration, provider failure, framework error and cookie-refresh path, must carry `Referrer-Policy: no-referrer` and `Cache-Control: no-store`. Apply headers after response recreation, with route-level/framework error coverage; do not assume middleware headers survive all responses. Keep the current exact route regex public for POST as well as GET; nested/lookalike paths do not become public. Denied register-subtree variants must also receive privacy headers without copying their path into redirects.

Never use token-bearing `redirect`, login `next`, Return-To, Location, exception URL, analytics route name, console output, trace span, breadcrumb, audit detail or metadata. A completion policy may eventually choose only an allowlisted token-free destination; provisional synthetic completion stays in place without a session. No raw token/hash/password/email/phone/request secret in logs, request dumps, server caches or telemetry. Do not log full RPC arguments/provider bodies or public URLs. Disable/redact platform access capture of `/register/*` and request bodies, including error/WAF layers, before real use. Local tests do not certify host configuration. Scrub synthetic test traces too; no screenshot of credential-bearing addresses as evidence. No third-party analytics/assets may receive the token via referrer.

Signed-in visitor behavior is owned only by `signup_authenticated_visitor_policy()`; prompt manual sign-out before registering; no automatic sign-out, linking, merge, staff conversion, extra membership or token redirect. Create pending-approval and deny client capabilities through both walls until admin approval. Approver roles/action scope ND-F11-6a and destination/session ND-F11-6b remain open (no access either way); no interim client view or approval UI. Completion policy is owned by `signup_completion_policy()`; initial generic completion must never imply approval/activation/plan access; no replay establishes a session.

## Audit and retention contract

Structured events cover attempts, success, failures, link consumption and cleanup (purge). Success/consumption events commit with signup; attempts/failures persist in the separate admission transaction/attempt log. No secrets, passwords, tokens/hashes or provider diagnostics; event names and payload allow-list are technical design. Signup-attempt logs without IP/ip_key retained 30 days; window-lived HMAC counters separate, purge mechanism local technical design; all other audit retention undecided (NEEDS SOURCE CONFIRMATION), ND-F5-1/B4 unchanged. Archived review mechanism/reviewer remains ND-F11-9a; archived behavior blocked until ND-F5-1 closure defines absent state (ND-F11-9b). D-16 unchanged.

## AD-F11-2 — architect decision: trusted IP and admission

Technical architect decision, not PO policy approval. The whole C1 privacy proposal below is **NEEDS SOURCE CONFIRMATION / PENDING PO**. AD-F11-1 remains PENDING PO; option (i) is a recommendation and C1–C4 are proposed evaluation criteria.

- On the Worker request trust only `CF-Connecting-IP` set by the Cloudflare edge; ignore `X-Forwarded-For` and all other IP headers. Absent in a production build → `unavailable` (fail closed). Local/test only: an explicit test-only override gated by a non-production flag. Test that it is never active in `build:edge` production output.
- The server action computes `ip_key = HMAC-SHA256(SIGNUP_RATE_KEY, normalized_ip)`. The secret is server-only, local value in `.env.local`, never sent to the browser or logged. Raw IP never leaves the server action and is never stored. Compute `link_key = HMAC-SHA256(SIGNUP_RATE_KEY, token_hash)` even for unknown/malformed links, with no link-row dependency or stored token hash.
- The anon-callable admission RPC cannot trust a supplied ip_key. Send `attestation = HMAC(SIGNUP_ATTEST_KEY, ip_key ‖ link_key ‖ issued_at ‖ nonce)` with shared unambiguous canonical encoding. DB verifies the same key held in Supabase Vault (local) / private schema, freshness ≤ 60 s, no future-issued timestamp and single-use nonce. Missing/invalid attestation or replay → generic `invalid`, no counter credit or ticket (no oracle). Attestation infrastructure failure → `unavailable`. DB independently verifies token-to-link_key binding and enforces per-link limits regardless of caller ip_key; forged attribution cannot bypass it.
- Counter storage: `app_private.signup_rate_counters(scope ∈ {link, ip}, key bytea, window_start, count, expires_at)`, no workspace/link FK, forced RLS, no grants. Advisory xact locks in fixed order: link key, then ip key, inside the separate admission transaction that commits before signup. Enforce both 5/link/15 min and 30/IP/hour across links/workspaces. What counts as an attempt and rolling versus fixed windows remain **ND-F11-5a — NEEDS SOURCE CONFIRMATION**, behind `client_signup_limits()`.
- Counter rows expire at window end (+ small slack); purge opportunistically on each admission and by the local purge job. Their retention is not 30 days. Keep private nonce/ticket security state separate from logs, forced RLS/no grants; nonce replay protection spans the freshness bound and ticket one-use integrity survives counter/log purge.
- `app_private.client_signup_attempts` stores outcome class, timestamp, and link_id/workspace_id ONLY when the link resolved (both NULL otherwise; same-workspace composite relation when present). No IP, ip_key, token, token hash, email/phone/name, or credentials. Retain 30 days (ND-F11-7). Failure evidence (ND-F11-10) is written here in the admission transaction independently of signup rollback. For a failure discovered after the initial admission committed, use a separate admission/evidence transaction after rollback; do not claim to amend an already committed transaction. Success/consumption evidence remains atomic with signup.

## Infrastructure-failure contract (I1)

Only infrastructure failures produce `{status:'unavailable'}`: DB unreachable, C1 Auth-compat guard failure, admission-attestation infrastructure failure (including absent trusted IP in production), or unexpected exception after rollback. HTTP 503, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`; generic English “Please try again later.” / Arabic “يرجى المحاولة مرة أخرى لاحقًا.” only, with no cause. Nothing is consumed on unavailable, including the link or admission ticket; roll back redemption on this path. Previously committed admission accounting remains durable.

Never derive unavailable from link or identity state: unknown/malformed/expired/consumed links, invalid attestation and exhausted limits stay `invalid`; valid-link identity collisions stay D-08 `duplicate`. Unresolved policy blocks implementation/configuration rather than creating a link/identity unavailable branch. F10 GET `/register/[token]` open contract, including `{status:'invalid'}`, is unchanged. UI retains the form for a later retry and never claims completion. Enumerate link/identity branches in tests and prove none selects unavailable.
