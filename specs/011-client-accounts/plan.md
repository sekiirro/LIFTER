## Phase 1 — Design and transaction boundary

Normative schema/grants/audit: [data-model.md](data-model.md). Public payloads, admission, middleware and F4: [contract](contracts/client-signup-surface.md). Verification: [quickstart.md](quickstart.md).

**Lock order (verbatim contract):** `link row FOR UPDATE → validity with authoritative clock_timestamp() after lock → request/ticket redemption (pre-admitted in a separate transaction) → canonical uniqueness locks in sorted key order and DB constraints → Auth identity/claim writes → client insert → guarded consume with fresh authoritative time → receipt and audit → deferred checks → COMMIT`.

**Transaction boundary (verbatim contract):** `Client insert + guarded registration-link consumption + successful-change audit (including deferred checks) + Auth user/identity + canonical claims + committed receipt commit in one database transaction; any failure rolls all signup effects back. Durable admission is separate; one-use ticket redemption precedes the inner signup subtransaction and business failures commit redemption without signup effects; infrastructure failures roll back redemption and return unavailable.`

Admission accounting commits durably before expensive work, with advisory link-key then ip-key locks separate from signup row locks. C1 runs before any write in each RPC. Redeem the one-use ticket outside the inner signup subtransaction; force deferred checks inside it. Every consumed-link retry is generic invalid, even with the same request secret after response loss. Receipts are internal dedup evidence only. Consumption uses fresh authoritative time after hashing/lock waits. No provider HTTP, reservation, pending gate, compensation or reconciliation is in the recommended, PO-pending signup design.

## AD-F11-2 — architect decision: trusted IP and admission

PO decision 2026-10-28: per-IP admission means per full IPv4 address (including mapped IPv4) and per IPv6 /64 network. Attestations accept issued_at up to 5 seconds ahead of DB clock_timestamp(), with an inclusive maximum age of 60 seconds. Nonces expire at issued_at + 60 seconds (up to 65 seconds after first acceptance); cleanup uses strict expiry so replay remains rejected at both inclusive edges. Timing constants have one private owner.

Technical architect decision, not PO policy approval. The C1 privacy proposal is **Decided (PO, 2026-10-28)**; Constitution unchanged. This C1 privacy decision is separate from AD-F11-1 option (i) and its binding C1–C4 conditions.

- U5 implements and tests a pure trusted-IP extractor: trust only `CF-Connecting-IP`, ignore `X-Forwarded-For` and all other IP headers, fail closed as unavailable when production IP is absent, and gate the explicit override to non-production. U6 wires the helper into the server action and owns the `build:edge` production-output proof.
- U5 implements and tests pure HMAC `ip_key`/`link_key` and attestation builders at their module boundary. Secrets remain server-only; raw IP stays within the server-action boundary. U6 wires these builders into the action and proves the test override is absent from `build:edge` output.
- Canonical encoding: attestation MAC input is ASCII("lifter.f11.attest.v1") || 0x00 || the following fields in fixed order, each encoded as uint32 big-endian byte length followed by raw bytes: ip_key (exactly 32 bytes), link_key (exactly 32 bytes), issued_at (canonical base-10 integer milliseconds since the Unix epoch, serialized as UTF-8), nonce (exactly 16 random bytes; UUID fields use their raw 16-byte form). Compute HMAC-SHA256(SIGNUP_ATTEST_KEY) over those bytes; reject non-32-byte MACs and compare the 32-byte MAC in constant time. Derive ip_key and link_key with HMAC-SHA256(SIGNUP_RATE_KEY, ASCII(domain_tag) || 0x00 || uint32be(byte_length) || raw_input), using domain tags "lifter.f11.ip.v1" and "lifter.f11.link.v1" respectively. The IP input is ASCII canonical text: full IPv4 dotted-quad (including IPv4-mapped IPv6 normalized to IPv4), or the IPv6 /64 network address with the last 64 bits zeroed, serialized in RFC 5952 lowercase compressed form without a slash (PO decision 2026-10-28); the link input is the ASCII bytes of the canonical 64-character lowercase-hex token_hash text. Create the shared implementation-time vector file at `tests/fixtures/f11-attestation-vectors.json` with at least three valid fixed vectors, including IPv6, plus a tampered case. T019 verifies DB acceptance of every valid vector and rejection of the tampered case; T022 verifies that the server builders reproduce the expected bytes for every valid vector and that tampering does not match the valid MAC.
- Counter storage: `app_private.signup_rate_counters(scope ∈ {link, ip}, key bytea, window_start, count, expires_at)`, no workspace/link FK, forced RLS, no grants. Advisory xact locks in fixed order: link key, then ip key, inside the separate admission transaction that commits before signup. Enforce both 5/link/15 min and 30/IP/hour across links/workspaces. ND-F11-5a decides every submission reaching admission counts (success or failure); fixed 15-minute link/1-hour IP windows aligned with expiry, behind `client_signup_limits()`.
- Counter rows expire at window end (automatic expiry; no usable counter beyond the window); purge opportunistically on each admission and by the local purge job. Their retention is not 30 days. Keep private nonce/ticket security state separate from logs, forced RLS/no grants; nonce replay protection spans the freshness bound and ticket one-use integrity survives counter/log purge.
- `app_private.client_signup_attempts` stores outcome class, timestamp, and link_id/workspace_id ONLY when the link resolved (both NULL otherwise; same-workspace composite relation when present). No IP, ip_key, token, token hash, email/phone/name, or credentials. Retain 30 days (ND-F11-7). Operational failure records are written here; ND-F11-10 additionally requires separate append-only audit_events in admission/evidence transactions independently of signup rollback. For a failure discovered after the initial admission committed, use a separate admission/evidence transaction after rollback; do not claim to amend an already committed transaction. Success/consumption evidence remains atomic with signup.

## Infrastructure-failure contract (I1)

Only infrastructure failures produce `{status:'unavailable'}`: DB unreachable, C1 Auth-compat guard failure, admission-attestation infrastructure failure (including absent trusted IP in production), or unexpected exception after rollback. `unavailable` payload with HTTP 200 from the same-route Server Action (PO decision 2026-10-28: Server Action transport, unavailable returned as payload with HTTP 200), `Cache-Control: no-store`, `Referrer-Policy: no-referrer`; generic English “Please try again later.” / Arabic “يرجى المحاولة مرة أخرى لاحقًا.” only, with no cause. Nothing is consumed on unavailable, including the link or admission ticket; roll back redemption on this path. Previously committed admission accounting remains durable. Auth-compat guard failure is specifically fail-closed before any DB write: no attempt/audit row or consumption; evidence is structured server-side event with only `code` and `timestamp`, fixed code `AUTH_COMPAT_GUARD_FAILED`, and no PII, IP, token or hash.

Never derive unavailable from link or identity state: unknown/malformed/expired/consumed links, invalid attestation and exhausted limits stay `invalid`; valid-link identity collisions stay D-08 `duplicate`. Unresolved policy blocks implementation/configuration rather than creating a link/identity unavailable branch. F10 GET `/register/[token]` open contract, including `{status:'invalid'}`, is unchanged. UI retains the form for a later retry and never claims completion. Enumerate link/identity branches in tests and prove none selects unavailable.

Pending-approval clients have **zero client access** through app `authorize()`, DB RLS (`has_workspace_access()` and client policies), direct PostgREST/RPC or Storage. **C1-audit split:** `app_private.client_signup_attempts` is the operational attempt log, purged after 30 days (ND-F11-7). Separately append `audit_events` rows for attempt/failure/success/consumption/cleanup (ND-F11-10). Both evidence payloads allow only outcome class, timestamp and link_id/workspace_id when resolved (both absent/NULL otherwise); no PII, raw IP, ip_key, token, hash, credential or provider payload. Admission writes attempt audit in its transaction; signup success and consumption audit commit in the atomic signup transaction. ### P-S40-5 Automatic balanced distribution (FR-028; S40-PO-13 MCQ-11 = Accept defaults)

- Concurrency (architect technical choice): distribution for one workspace runs under a per-workspace lock taken before reading trainer balances, so that concurrent approvals see a consistent balance and each approval yields at most one automatic row. Tests: T058.
