# Research: P0-F2 Design System

| Topic | Decision | Rationale | Alternatives |
|---|---|---|---|
| Styling | CSS custom properties plus CSS Modules, logical properties only | No new dependency. Direction-agnostic by construction. Works with server components. | Tailwind (extra toolchain); CSS-in-JS (runtime cost, RSC friction) |
| Token source of truth | `lib/design/tokens.ts` (typed) → `tokensToCss()` → inline `<style>` in the root layout | One source for both the CSS and the contrast tests, with no generated files to keep in sync | Hand-written CSS that tests parse (drift risk); a build script (extra step) |
| First-paint theme | Server reads `lifter_theme`. When it is absent, `<html>` gets no `data-theme` and CSS `@media (prefers-color-scheme)` picks the mode. When it is set, `data-theme` is set on the server. | No flash, works with JS off and with storage blocked. Follows live device changes when no manual choice is saved. | Inline blocking script (needs JS and a CSP exception) |
| First-paint language | Server reads `lifter_locale` (default `ar`) → `<html lang dir>` | Same reasons as the theme | Locale URL segments (`/ar/...`): more routing work, with no SEO need since public marketing pages are excluded by PRD-12 |
| Preference persistence | Cookies: `Path=/; Max-Age=31536000; SameSite=Lax`, not HttpOnly (the client switcher writes them), values from a strict allow-list | Readable on the server for the first paint. No PII. | localStorage (the server can't read it, so the page flashes) |
| i18n | Plain typed catalogs. `en` is typed as `Record<keyof typeof ar, string>`, and a unit test checks key parity. | 2 locales, small surface, no dependency | next-intl (fine later if plurals/ICU become necessary) |
| Contrast math | WCAG 2.x relative luminance and contrast ratio | WCAG 2.2 AA is the target (spec FR-003) | APCA (not yet normative) |
| Brand derivation | For each mode: (a) **fill** for primary buttons: keep the brand hue and chroma, choose the label among white and `#0B0C0E` with the smallest OKLCH-lightness change of the fill that reaches 4.5:1 (no change when the raw color already passes); (b) **brand text** (links and active nav labels on the surface) at ≥4.5:1 against card and background; (c) **focus ring / active indicator** at ≥3:1 against the background. Adjustment is a binary search on OKLCH L, clamped to the sRGB gamut. Invalid hex → default brand. | Deterministic, pure and testable. It preserves the approved emerald exactly when that is possible: `#059669` with the dark label scores ≈5.2:1, so the fill stays unchanged. | Fixed hand-picked shades (don't generalize to workspace colors); HSL lightness (perceptually uneven) |
| **F2-proposed values (ND-1)** | Surfaces start from the DESIGN.md samples. Dark: bg `#101113`, card `#1B1D20`, border `#303237`. Light: bg `#F6F7F8`, card `#FFFFFF`, border `#E5E7EB`. Text and muted text plus the semantic colors are chosen by the implementer and **must pass the contrast tests**. Borders of interactive controls need ≥3:1; decorative separators are exempt. The final values are listed in the PR for PO review. | DESIGN.md: secondary values are not approved, so create them within the feature with contrast evidence | — |
| Workspace brand at runtime | `<BrandScope color>` sets inline `--brand-*-light` / `--brand-*-dark` variables on a wrapper element marked `data-brand-scope`. The mode-mapping selectors that apply to `:root` also apply to `[data-brand-scope]`, so the scope re-resolves `--brand-fill` and the related variables. | Server-renderable, no JS. Nested scopes work. | Re-injecting a whole stylesheet per workspace |
| Semantic colors | A fixed set (success, warning, error, info), each with fg/bg/border tokens per mode, never derived from the brand. Status is always also given by an icon and text. | DESIGN.md §2 and the "not by color alone" rule | — |
| Fonts | `next/font/local` with the WOFF2 files from `geist` (Geist Sans variable) and `@fontsource/ibm-plex-sans-arabic` (weights 400, 500, 600, 700; arabic + latin subsets), exposed as CSS variables. Locale-ordered stacks: `:lang(ar)` → Plex Arabic, Geist, system-ui; `:lang(en)` → Geist, Plex Arabic, system-ui. `display: swap`. | Self-hosted with no runtime CDN. Both are OFL 1.1, which allows commercial use; the license was checked through the npm metadata on 2026-10-27, and the implementer must also confirm the LICENSE files in the packages. | `next/font/google` (build needs network; less reproducible) |
| Icons (ND-2) | Hand-authored 24-px outline SVG icons (stroke `currentColor`, width 1.75, round caps). `mirrorInRtl` flag only for directional icons. | Tiny, with no dependency; the final library is open | lucide-react (a good candidate later; choosing it is a PO-level open item) |
| Dialog | Native `<dialog>` + `showModal()` (top layer, inert background, Escape), with explicit focus restore to the trigger and `aria-labelledby` | Platform-correct focus containment with the least code | Custom focus trap |
| Toast | Context provider, a single `role="status"` / `aria-live="polite"` region, auto-dismiss after about 5 s (paused on hover and focus), success only | DESIGN.md §4 feedback rules | — |
| Motion | Tokens `--motion-fast: 150ms`, `--motion-base: 200ms`, `--motion-slow: 250ms`. `@media (prefers-reduced-motion: reduce)` sets durations to `0.01ms`. | DESIGN.md §4 | — |
| Responsive nav (ND-3) | Both the rail and the bottom bar are rendered on the server, and CSS shows one per media query `(min-width: 48rem)`. The hidden one is `display:none`, so it is out of the accessibility tree. | No JS, no layout flash | JS width detection |
| Showcase gate | `isShowcaseEnabled(env)` is true only when `LIFTER_SHOWCASE === '1'`. Pages call `notFound()` otherwise. Playwright's `webServer` sets the flag. Production/OpenNext never sets it. | E2E runs against the production build, so `NODE_ENV` can't be the gate | `NODE_ENV` check (would block e2e) |
| A11y testing | `@axe-core/playwright` with tags wcag2a/aa, wcag21a/aa and wcag22aa; fail on serious and critical violations | SC-002 | Manual-only |
| Logical-CSS guard | A unit test scans `app/**/*.css` and `components/**/*.css` for physical properties (`margin-left/right`, `padding-left/right`, `left:`/`right:` for positioning, `border-left/right`, `text-align: left/right`, `float: left/right`) and fails on any match | Enforces FR-009 without stylelint | stylelint (extra dependency) |
| Print spike | The dev-only `/print-sample` page uses `@media print` (hide chrome, A4 margins provisional, table header repeat via `thead { display: table-header-group }`, `break-inside: avoid` on rows). An e2e test produces a PDF with Chromium `page.pdf()` into `test-results/`. The reviewer inspects it and writes `print-spike.md`. | Headless Chromium print is the same engine as browser print-to-PDF (Architecture v3) | Server PDF (not on the free plan) |
