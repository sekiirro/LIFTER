## 6. Atomicity — PASS

- One transaction end to end; the script refuses to run outside `--single-transaction` (`:163–165`), timeouts are positive and pinned (`:91–93`, asserted `:257–263`; `0`/unset refuses — executed `…test.ts:1311–1339`).
- Every DELETE uses `RETURNING`: package delete is compared as an id array to the allow-list (`:478–485`); version/offer deletes are compared by count against lock-time snapshots whose rows are matched by primary key (`:456–475`; `id` is the PK of both tables — `20261029120000_packages.sql:9,23` — so count equality implies set equality), and `targets_remain` re-checks that no target row survived (`:528–532`).
- Post-conditions before COMMIT: trigger inventory, function and constraint hashes, non-target row counts, zero targets remaining, one teardown event per package (`:493–536`). Any failure raises `C5001` → whole transaction rolls back.
- Rollback invariant (D5) with the single documented non-transactional exception: `…test.ts:1033–1091` snapshots row content/hashes plus triggers, constraints, grants and function hashes, refuses before and after the audit insert, asserts full identity, and demonstrates that only `audit_events_id_seq` advanced.
- Concurrency: EXCLUSIVE lock in fixed order (`:310`) with the preflight re-run under it; executed blocking test plus a no-LOCK mutant proving the lock matters (`…test.ts:1543–1588`).
