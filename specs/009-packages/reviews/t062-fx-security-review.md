## Checklist

1. **PASS — Outbound data minimization.** The only provider request builder fixes `base`, `quotes`, `providers`, `from`, and `to` (`lib/packages/fx.ts:226-239`). Fetch is GET with no body, `credentials: 'omit'`, and only `accept: application/json` (`:373-381`). Calendar-month dates are derived from the transaction instant; no exact instant, workspace/client/user identifiers or customer data are passed. T059 tests `URL pins provider, pair and window and carries nothing else` and `captured request has no body, cookies, auth or client/workspace data` (`tests/unit/packages-fx-adapter.test.ts:51-82`).
2. **PASS — Destination and resource bounds.** Fixed HTTPS origin/path is `https://api.frankfurter.dev/v2` and `/rates` (`:56, 226-239`); no URL/host/path is supplied by a caller. Invalid/unpinned currencies fail before fetch (`:357-370`; T062 test `unpinned currency ... before any network call`, `:432-456`). Redirects are rejected (`:378`; captured-request test above). Timeout defaults to 5s and clamps at 15s (`:58-61, 292-297, 367-370`); declared and streamed bodies are capped at 256 KiB and response rows at 100 (`:59-60, 254-257, 300-319, 384-390`). T059/T062 tests cover redirect option, abort timeout, declared/streamed oversize, and row-count/schema rejection (`:68-82, 298-315, 488-518`).
3. **PASS — Validation and fail-closed behavior, with F-1 provenance limitation below.** Exact row keys, base/quote, valid date/window, provider calendar, unique dates, finite positive rates and per-currency bounds are enforced (`:254-289`). Pin map is USD→CBE, SAR→SAMA (`:96-100`). Every fetch/HTTP/timeout/parse/validation/empty or unsettled failure returns `pending`; no fallback rate is assumed (`:347-398`). Tests include `rejects %s -> pending, never throws`, `network error -> pending`, `empty publications -> pending`, `implausible ... rate ... is rejected`, and settle-boundary cases (`tests/unit/packages-fx-adapter.test.ts:214-315, 364-397, 459-486`).
4. **PASS — Secrets.** No provider secret/configuration or auth header is needed; destination is a constant and request headers contain only JSON accept (`:56, 373-381`). No secret value is logged; there are no logging calls in the adapter (`:357-400`).
5. **PASS — Logging/audit minimization.** The adapter contains no log/audit emission and no call-site forwards request data to an audit path. Repository search found only the adapter definition and unit-test references to `fetchFxSnapshot`; the request carries only the fields in item 1.
6. **PASS — Snapshot persistence/RLS.** No FX snapshot table or FX RPC was found under `supabase/`; the reviewed adapter is a pure server-side fetch/selection helper and has no production caller in `origin/main`. Thus there is no snapshot write path or associated RLS/authz policy in scope. Recheck this when persistence/callers are added.
7. **FAIL — Test coverage is substantial but does not close every review condition.** T059 adapter tests verify minimization, request options, malformed responses, bounds, timeout, size, and pending behavior (names cited above). T075 evidence is `specs/009-packages/fx-coverage-verification.md` (manual live-provider coverage record, including S61-PO-1 and S65 re-verification), not an executable security test. No automated test can establish SAMA row provenance from the current response schema; it lacks a provider field (F-1). No database/RLS test applies because no FX persistence path exists. Static inspection found no logging path.
