# T064b independent security review

**Reviewed:** `specs/009-packages/reviews/t064b-teardown-design.md` on PR #249 head `3c43c258cd25025c8dfc383714e04be5253709ab`.
**Reviewer:** independent security review; design author was not consulted for authorship.
**Verdict: FAIL.** T064b remains unticked. No design or code was changed by this review.

## Checks

| Check | Result | Evidence and assessment |
|---|---|---|
| Actor authority: owner-only, no persistent capability | **PASS** | Design A1–A3 limits execution to the database owner with `BYPASSRLS`, by hand, and excludes application roles, functions, grants, RPCs, jobs, and APIs (`t064b-teardown-design.md:47–50`). This matches the owner-only transient procedure in S61-PO-2 (`docs/04-changes-and-questions.md:1635–1638`). |
| Workspace and stack scope | **PASS** | Stack identity is checked against a cluster-unique identifier and allow-list, empty input is refused, and the verified workspace set must equal the preflight set (`t064b-teardown-design.md:51, 56–60, 72`). T064a v2 returns explicit input mode, targets, and workspace IDs (`supabase/migrations/20261121110000_f9_c5_package_preflight_v2.sql:315–326`). |
| Atomicity | **FAIL** | The design requires a refused run to leave the stack “byte-identical” (`t064b-teardown-design.md:76–80, 119`). The required teardown audit insert allocates `audit_events.id` from a `bigint ... generated always as identity` sequence (`supabase/migrations/20261027150000_audit_log.sql:2–10`). PostgreSQL does not reclaim `nextval` values after an aborted transaction ([official sequence documentation](https://www.postgresql.org/docs/18/functions-sequence.html)), so a late assertion failure after the audit insert can leave a sequence gap even though table rows and trigger DDL roll back. The promised state is not achievable as written. |
| Audit preservation | **PASS** | Existing audit events are retained; audit rows naming a mock do not block per Q1=A, and new teardown events are transactional and allow-listed (`t064b-teardown-design.md:64, 84–86`; PO record `docs/04-changes-and-questions.md:1635–1638`). The preflight explicitly separates named mock audit rows from blocking financial/client audit rows (`supabase/migrations/20261121110000_f9_c5_package_preflight_v2.sql:190–208`). |
| FR-006 immutability | **PASS** | No guard, RLS, grant, or FK change is permitted; only verified synthetic rows enter the delete set; remaining published versions must still reject update/delete/truncate (`t064b-teardown-design.md:90–93`; `specs/009-packages/spec.md:301`). |
| Trigger disablement is exactly the approved carve-out | **PASS** | Only the three named per-table delete triggers, one at a time around their respective delete, and `package_offers_guard` for the single `current_version_id := NULL` update are allowed; the offer guard must be restored before any delete. All other trigger classes and replica mode are forbidden (`t064b-teardown-design.md:67–70`). This is within Q2=A/Q3=A (`docs/04-changes-and-questions.md:1635–1638`). |
| Restrictive-reference handling | **PASS** | The design keeps validated RESTRICT/NO ACTION FKs, forbids cascades/truncation/FK changes, re-runs preflight under locks, and refuses dependent or unknown rows (`t064b-teardown-design.md:64–72`). Installed package FKs and guards are sourced in the design (`t064b-teardown-design.md:24–29`). |
| Refusal/escalation for unsafe or unknown rows | **PASS** | Unknown dependencies, non-synthetic rows, unobservable rows, unsafe preflight states, and mismatches refuse before deletion and escalate without exposing row data (`t064b-teardown-design.md:97–99`). The T064a preflight treats unknown references as `unknown_dependency_state`/escalation (`supabase/migrations/20261121110000_f9_c5_package_preflight_v2.sql:138–157, 235–280`). |
| Fail-closed replication, trigger, and guard-hash checks | **PASS** | Design requires `session_replication_role = origin`, exact enabled trigger inventory, no “repair” of unexpected state, and before/after function and constraint hashes (`t064b-teardown-design.md:69–72`). These controls align with the operator draft’s checks (`supabase/cleanup/20261121_t065_c5_mock_package_teardown.sql:128–198, 307–334`). |
| Test plan completeness | **FAIL** | The plan does not explicitly require a workspace-list **superset** refusal or extra/missing non-internal-trigger mutants, although the design mandates exact workspace equality and exact trigger inventory (`t064b-teardown-design.md:58, 69–71, 109–120`). The draft tests already exercise these cases (`tests/integration/packages-c5-teardown.test.ts:474–480, 527–533`), but the plan should preserve them as required cases. The plan also requires testing published-version update/delete/truncate protection for every role (`t064b-teardown-design.md:93, 117`), while the draft post-run test only checks package delete/truncate and audit update (`tests/integration/packages-c5-teardown.test.ts:168–179`). |
| “Draft T065 divergences” inventory complete and accurate | **FAIL** | D1 omits A4’s required UTC run timestamp and captured preflight output/capture timestamp (`t064b-teardown-design.md:50, 132`; draft header `supabase/cleanup/20261121_t065_c5_mock_package_teardown.sql:24–25`). D5 says the draft tests do not execute unvalidated-FK, rewrite-rule, or non-restrictive-FK refusals, but they do (`tests/integration/packages-c5-teardown.test.ts:446–478`); it should isolate the actually uncovered internal-FK-trigger and constraint-hash cases (`t064b-teardown-design.md:136`). D6 describes text checks as replacing runtime mutants, but its cited cases execute mutated script variants and assert refusal/rollback (`tests/integration/packages-c5-teardown.test.ts:393–432`). Finally, section 9 omits the gap in post-run FR-006 regression coverage cited in the test-plan row above. |

## BLOCKING fixes before T064b PASS

1. Replace or qualify the “byte-identical stack” rollback guarantee to account for non-transactional identity-sequence advancement, and make the required rollback evidence test the stated, achievable invariant (`t064b-teardown-design.md:80, 119`; `supabase/migrations/20261027150000_audit_log.sql:2–10`).
2. Make section 7 explicitly require exact workspace-set and unexpected/missing user-trigger cases, plus post-run published-version update/delete/truncate attempts across every role; keep them as required T065 tests (`t064b-teardown-design.md:109–120`).
3. Reconcile section 9 against the script and companion tests: add the missing A4 provenance fields and FR-006 regression-test gap; correct D5/D6 so they describe only genuinely uncovered or unexecuted behavior (`t064b-teardown-design.md:128–144`).

Because these blockers remain, T064b is **not** ticked in `specs/009-packages/tasks.md:199`.
